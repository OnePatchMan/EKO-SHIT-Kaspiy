# EcoShield AI

ИИ модуль участника 3 для кейса «Эко-Щит Каспия». Java сервер вызывает этот сервис по HTTP, сохраняет результаты и передаёт их в дашборд. Интерфейс команды, Java приложение и физические датчики в этот пакет не входят.

В составе: готовая аудионейросеть YAMNet, сценарный расчёт будущих гидрологических условий для сазана, базовый Computer Vision для сравнения снимков, проверка IoT показаний и демонстрационный генератор.

## Что действительно делает каждая технология

| Направление | Реализация | Граница результата |
|---|---|---|
| Audio Processing | Декодирование WAV, mono, настоящий ресемплинг 16 кГц, анализ временных окон | Подводные гидрофоны отдельно не проверены |
| ML/DL | Настоящая YAMNet на официальных предварительно обученных весах | Нет собственного дообучения; score не равен вероятности браконьерства |
| Computer Vision | Сравнение двух пространственно совмещённых RGB снимков и координаты изменившихся областей | Это классический CV алгоритм, без обученной модели сетей / сбросов; облака и тени могут давать изменения |
| IoT | Схема времени, единиц и происхождения измерений, проверка пакетов, генератор синтетического показания | Нет подключённого оборудования; хранение и приём потока в продукте выполняет Java |
| Предиктивная аналитика | Сценарий на 24/48/72 часа, простой тренд воды, объяснение факторов | Фактический нерест и точность биологического прогноза не подтверждены |

## Быстрый запуск

Нужен 64-битный Python 3.12. CPU достаточно. Команды ниже выполняются в папке этого проекта.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe -m uvicorn ecoshield.api:app --host 127.0.0.1 --port 8001
```

Если файл фиксации окружения не используется, установите `requirements.txt`. В исходном пакете должны быть локальные `models/yamnet.h5` и `vendor/yamnet`. Для их повторного получения и загрузки демонстрационных аудиофайлов:

```powershell
.\.venv\Scripts\python.exe scripts/setup_assets.py
.\.venv\Scripts\python.exe scripts/make_demo_data.py
```

Документация API: http://127.0.0.1:8001/docs. Проверка готовности: http://127.0.0.1:8001/health. Первичная загрузка TensorFlow может занять время; поле `audio_model_ready` должно стать `true`. Если модель недоступна, аудиометод вернёт 503, без подставного результата. После установки библиотек и получения ресурсов сам анализ работает без обращения к модельному хабу.

`start.ps1 -Python <путь к python.exe>` запускает тот же сервис. По умолчанию сервис доступен только на локальном компьютере. При переносе между компьютерами Java разработчик настраивает адрес и доступ отдельно.

## Демонстрация для защиты

1. В `/docs` открыть `POST /v1/audio/analyze`. Выбрать `data/audio/boat_river_germany.wav`, station_id=`delta-demo-01`, recorded_at=`2026-05-10T09:00:00Z`. Сервис вернёт оценки модели и интервалы событий; результат конкретного файла смотрите в отчёте.
2. Проверить также реку, автомобильный двигатель, эффект выстрела и `boat_thailand.wav`, где готовая модель пропускает лодку. Показать удачные исходы и ограничения по `reports/AUDIO_CONTROLS.md`. Второй независимый пример лодки добавлен после первого прогона, пороги при этом не менялись.
3. Вызвать `POST /v1/spawning/forecast` с `examples/forecast_request.json`. Это синтетический весенний сценарий, воспроизводимый относительно issued_at 10 мая 2026, а не текущий мониторинг в ноябре. В ответе будет будущий для сценария период и `is_demo=true`.
4. Вызвать `POST /v1/images/compare` на `data/images/synthetic_before.png` и `synthetic_after.png`. Указать aligned=true, is_demo=true и две даты в правильном порядке. Это синтетические тестовые рисунки, не спутниковые снимки.
5. Выполнить `python scripts/simulate_iot.py` и показать нормализованные значения с `stored=false`. Реальный Java сервер должен сохранить их и связать со станцией.

Полный сценарий «интерфейс → Java → Python → карта» считается проверенным только после подключения к приложению участников 1 и 2. Самостоятельный прогон Python сервиса этого не доказывает.

## Проверка и дообучение

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
$env:ECOSHIELD_REAL_MODEL='1'
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe scripts/evaluate.py
```

Первый запуск пропускает одну проверку реальной модели, второй её включает. `reports/VALIDATION.md` содержит результаты фактических проверок. Контракт для Java: `docs/JAVA_INTEGRATION.md`. Следующий этап обучения: `docs/TRAINING_NEXT.md`. Источники, лицензии, преобразования аудио и хэши: `data/manifest.json`.

Обязательный биологический прогноз кейса остаётся неподтверждённой частью. Сценарный модуль показывает механику расчёта и подключения. Для обучения и независимой проверки фактического нереста нужны сопоставленные гидрологические и биологические наблюдения по территории, виду и сезонам.
