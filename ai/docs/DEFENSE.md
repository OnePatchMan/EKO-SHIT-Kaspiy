# Технический сценарий защиты

Цель — показать цифрового помощника инспектора, который объединяет разнородные наблюдения и помогает выбирать события для проверки и будущие периоды для патрулирования.

## Короткое объяснение

«Мы разделили систему на карту инспектора, Java сервер с данными и Python сервис аналитики. Для звука используется настоящая предварительно обученная YAMNet. Она получает WAV, анализирует временные окна и возвращает типы предполагаемых звуков, интервалы и оценки. Java сохраняет результат и показывает событие у станции. Сам звук двигателя не доказывает браконьерство — инспектор проверяет контекст.

Для воды мы согласовали время, единицы, источник и качество показаний. До доступа к данным территории показываем воспроизводимый сценарий будущих гидрологических условий для одного вида рыб. На экране видны период, допущения и недостающие данные. Это не подтверждённая вероятность нереста.

Computer Vision сравнивает подготовленную пару изображений и выделяет изменения для просмотра. IoT поток пока демонстрируется генератором с явной маркировкой. После получения местных данных мы дообучим и проверим аудиоклассификатор, сопоставим гидрологию с наблюдениями нереста и измерим качество на независимых периодах».

Говорить «Java сохраняет и показывает» как о выполненном можно только после фактического подключения командного сервера и интерфейса. До этого показывается HTTP контракт Python сервиса и говорится «Java будет сохранять и показывать».

## Что предъявить как доказательство

- Запрос к реальному локальному сервису с файлом и сохранённый JSON результата. Не использовать ответы, зависящие от имени файла.
- Контрольные записи и таблицу ошибок. Четыре демонстрационных файла не подтверждают качество на всей территории.
- Сценарий воды, будущие относительно issued_at даты и изменение результата при изменении входов.
- Разницу двух синтетических изображений с надписью о происхождении. Для реальных спутниковых сцен нужна отдельная проверка.
- Источники и лицензии, версии модели, протокол тестов и точный план получения биологической разметки.

## Ответы на вероятные вопросы

**Почему не обучали большую сеть с нуля?** Кейс допускает обученную модель или пайплайн. Готовая звуковая модель даёт проверяемую основу до доступа к местным данным; дообучение сравнивается с ней по качеству.

**Что означает score?** Это выход модели для класса звука. В этой версии он не калиброван как вероятность и не равен вероятности незаконной деятельности.

**Где точность прогноза нереста?** Пока не измерена. Показан расчёт условий на демонстрационных данных. Для биологической проверки нужны сопоставленные наблюдения по участку, виду и нескольким сезонам; отсутствие наблюдения не всегда означает отсутствие нереста.

**Где реальные датчики и спутниковая аналитика?** В этом пакете есть проверяемый формат IoT и базовый алгоритм сравнения изображений. Физическое оборудование и спутниковый классификатор нарушений отдельно не реализованы. Основной нейросетевой вариант MVP — аудио, что допускается формулировкой кейса.

**Что требуется от организаторов после отбора?** Доступные записи с описанием микрофона и условий, гидрологические ряды с единицами и нулём поста, пространственная привязка, наблюдения нереста и описание метода / усилия наблюдения. Сначала аудит этих данных, затем обучение и независимая проверка.
