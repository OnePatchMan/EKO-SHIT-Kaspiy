# Продуктовый бриф Эко Щит Каспия

## Цель и пользователь

Продукт помогает инспектору ООПТ сопоставлять наблюдения воды, звук и изображения с территорией и временем, замечать события для проверки и планировать патрулирование. Первая гипотеза: единая карточка события с исходными данными и объяснением результата позволяет пройти путь от наблюдения к решению о проверке без переключения между разрозненными источниками.

Эта гипотеза ещё не проверена на реальных инспекторах. Организаторы предоставят местные данные только после победы; до этого демонстрация использует открытые звуковые записи и явно маркированные синтетические сценарии.

## Пользовательские сценарии

- Как инспектор, я хочу увидеть у станции предполагаемый звук лодки или выстрела и открыть запись, чтобы решить, нужна ли проверка.
- Как инспектор, я хочу видеть период, факторы и ограничения расчёта условий нереста, чтобы осмысленно планировать патрулирование.
- Как инспектор, я хочу сравнить подготовленные изображения и увидеть изменившиеся области, чтобы выбрать место для просмотра.
- Как оператор данных, я хочу проверять время, единицы и происхождение показаний, чтобы не смешивать несовместимые измерения.
- Как разработчик Java сервера, я хочу получать воспроизводимые JSON ответы и явные ошибки, чтобы связать аналитику с картой и хранением.

## Доказательства для отбора

Показать фактический запрос с файлом и JSON ответ, контрольные исходы с ошибками, сценарий изменения воды, изображение с выделенным изменением, протокол проверки и план независимой валидации. Проценты точности, экономический эффект и сокращение времени инспектора не выдумываются. Для оценки пользы на следующем этапе нужны реальные инспекторы и измерение времени разбора / числа полезных и ложных предупреждений.

Полный командный продукт и биологический прогноз не объявляются готовыми только на основании готовности этого сервиса.

## Архитектурные решения и компромиссы

- Python выбран для готовой ML модели и обработки численных / звуковых данных; Java сохраняет роль основного сервера. Компромисс — два процесса и явный HTTP контракт.
- Модель загружается один раз, веса хранятся локально. Это уменьшает задержку повторных вызовов и зависимость демонстрации от сети, но требует памяти и времени первичного запуска.
- Синхронные ограниченные запросы упрощают подключение в хакатоне. Параллельная промышленная нагрузка потребует очереди и отдельного масштабирования.
- Аналитика не хранит предметные данные и не решает, законна ли деятельность. Источник фактов, станции, предупреждения и доступ пользователей контролирует основной Java сервер.
- Запуск ограничен loopback интерфейсом локального компьютера. Публичное размещение и авторизация — отдельная задача после интеграции; этот пакет не позиционируется как готовый публичный сервис.
